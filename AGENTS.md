# RPG Harness — заметки для агентов

Харнес, в котором нейросеть ведёт текстовую RPG как гейм-мастер для одного игрока. Модель рассказывает
историю и вызывает инструменты (tool calls). Харнес хранит состояние, считает честные числа (кости,
баланс, опыт, добычу, цены) и показывает всё в интерфейсе: книга героя, окна боя, торговли и гильдии.

Главный принцип архитектуры: **модель решает, _что_ происходит, харнес решает, _сколько_.** Любое число,
которое модель могла бы выдумать (броски, ХП/КБ врагов, опыт, добыча, характеристики спутника), должно
считаться кодом и приходить модели результатом инструмента.

Язык проекта — русский: UI, промпт, комментарии, доки, сообщения инструментов. Пользователь пишет по-русски.

---

## Стек и запуск

- .NET 10, Blazor Server (Interactive Server), один проект `RPG_Harness.csproj`. Зависимость — Markdig.
- Сборка: `dotnet build`. Запуск: `dotnet run` (профиль `http` → http://localhost:5193).
- Настройки — `.harness/settings.json` рядом с проектом (`AppPaths`): адрес OpenAI-совместимого API,
  **ключ API** (не выводить в логи и ответы), модель, системный промпт, рабочая директория, профили запросов,
  тема оформления (`Theme` → `UiThemes`), она же сеттинг игры (см. «Сеттинги»).
- Данные игры лежат в рабочей директории из настроек: `chats/` (диалоги), `rpg/` (состояние кампаний в JSON),
  `campaigns/<папка чата>/` (markdown-файлы кампании). Без рабочей директории всё живёт в памяти.
- Git в проекте нет. Перед крупными правками делайте архив исходников (без `bin`, `obj`, `.vs`, `nul.xml`).

## Как проходит ход мастера

`Chat.razor` (метод отправки, около строки 1000):

1. Перед ходом сохраняется снимок состояния (`RpgStore.SaveSnapshot`) — на нём работает «Переиграть ход».
2. Вид запроса (`DetectKind`): `world` на этапах сессии ноль и выбора арки, `combat` при живых противниках,
   `story`, `trade`, `ooc` (режим «Игрок»). У каждого вида свои температура и глубина рассуждений (`RequestKinds`).
3. Системный промпт = `settings.SystemPrompt` + служебные заметки `LlmClient` + **сводка `FileTools.BuildStateNote`**
   (этап кампании, книга героя, группа, противники, арка, мир; при обрезанной истории — хвост Journal.md).
4. Модель отвечает; каждый tool call выполняется `FileTools.Execute(campaignDir, name, argsJson, chatId)`,
   результат уходит обратно модели как `role=tool`. Параллельно `BattleLogFeed` пишет журнал боя, а некоторые
   вызовы открывают окна (`open_trade`, `open_adventure_guild`, `update_adversary`, `plan_encounter`).
5. Цикл повторяется до финального текста или до инструмента из `FileTools.WaitForPlayerTools`
   (`offer_choices`, `propose_arcs`, `open_trade`, `open_adventure_guild`, `ask_companion_role`) — тогда ход
   заканчивается и ждём игрока. Лимит — `MaxToolRounds = 24` раунда.

Этапы кампании (`FileTools.GetPhase`): сессия ноль (World.md — пустой шаблон) → выбор арки → приключение.
Новый чат стартует сам: `CharacterCreator` → `ChatCreationFlow.MarkKickoff` → скрытое сообщение `GmPrompt.KickoffMessage`.

Изолированные сцены (`start_instance` / `finish_instance`, если включено в настройках): суб-мастер ведёт данж
или долгий бой в отдельном контексте (`RpgState.ActiveInstance`), затем передаёт сводку основному мастеру.

## Состояние и файлы кампании

- Источник правды — `RpgState` в `{WorkDirectory}/rpg/{chatId}.json`. Меняется только инструментами и UI,
  после изменения — `RpgStateStore.Save`.
- `RpgStateStore` зеркалит состояние в markdown: `Hero.md`, `Inventory.md`, `Characters/*.md` (NPC и лавки),
  `Characters/Party/*.md`, `Adversaries.md`, `Quests.md`, `Story_Arc.md`, `Cities.md`, `Instances.md`,
  `Worldstate.md`. Модели запрещено писать в них `create_file` — только инструменты. Исключение: ручные правки
  **человеком** в `Hero.md` подхватываются обратно в состояние (`TryParseHeroMd`).
- Файлы, которые ведёт сама модель (`create_file`/`edit_file`): World.md, Rules.md, Factions.md, Bestiary.md,
  Secrets.md, Journal.md. Их шаблоны — `CampaignTemplates`; незаполненный шаблон можно перезаписать без
  `overwrite` (`IsUnfilled`). Меняя шаблон, добавьте примету старой версии в `IsUnfilled`, иначе уже созданные,
  но не заполненные кампании перестанут считаться незаполненными.
- Файловые инструменты ограничены папкой кампании (`ResolveSafe`).
- «Взаимодействия неподалёку» — это nearby-NPC с местом, совпадающим с текущей сценой
  (`RpgState.NearbyHere()`: `ImportantNpc.NearbyPlace` == `RpgState.ScenePlace`). Место сцены меняет
  только харнес: `travel` (from/to, короткий переход `short` внутри поселения не считается),
  `set_world_state` с параметром `place` и границы инстанса (`start_instance` / `finish_instance`).
  Так торговцы города не светятся, пока герой в лесу, и снова появляются по возвращении; новых nearby
  модель заводит уже на месте (`update_npc category=nearby`, `set_merchant`). NPC к месту не приклеены:
  повторный `update_npc category=nearby` или `set_merchant` перевязывает их к текущему месту сцены
  (переехал, приехал вслед, встретился в новом городе) и освобождает прежнее.

## Инструменты модели

Около 40 инструментов, определения — в `FileTools.BuildDefinitions()` и `FileTools.ExtraDefinitions()`
(`FileTools.Progression.cs`). Хелперы схемы: `Def(name, desc, (param, type, desc, required)...)` для плоских
параметров и `RawDef(name, desc, JsonObject properties, required...)` для массивов/объектов.

**Как добавить инструмент:**
1. Определение в `BuildDefinitions` или `ExtraDefinitions`.
2. Ветка в `switch` внутри `Execute` и реализация, возвращающая `(bool Ok, string Result)`. Текст результата —
   инструкция для модели: что сделано, итоговые числа и что делать дальше. Ошибки начинаются с «Ошибка:» и
   объясняют, как исправить вызов.
3. Если инструмент требует чата — имя в `RpgTools` (`FileTools.cs`) или `ProgressionTools` (`FileTools.Progression.cs`).
4. Если после него игрок должен выбрать — в `WaitForPlayerTools` и отрисовка в `Chat.razor`.
5. В `Chat.razor`: подпись в `ToolLabel` и `ToolTitle`; если у инструмента своя карточка — исключить его из `bookCalls`.
6. Упомянуть инструмент в `GmPrompt.Default` (и в `SettingsPage.razor`, если он заметен игроку).

**Разбор аргументов.** Модели присылают числа строками, объекты вместо строк и т.п. Старые хелперы
`OptInt`/`Arg`/`OptBool` бросают исключение на неверном типе (его ловит `Execute` и возвращает ошибку); в новом
коде используйте устойчивые `Num`/`Str`/`Flag` (`FileTools.Progression.cs`).

**Размер.** Описания всех инструментов уходят в каждый запрос (~58 тыс. символов). Длинные справочники
(каталоги иконок и портретов) держите компактными и в одном месте; другие инструменты ссылаются «см. update_…».

## Сеттинги (Фэнтези / Киберпанк / Современность)

Тема в настройках — это сеттинг игры, а не только оформление. `SettingsService` выставляет `Genre.Current`
по теме; от него зависят промпт мастера (`settings.PromptFor`: `SystemPrompt`, `SystemPromptCyber` или
`SystemPromptModern`, у каждого своя авто-актуализация), описания инструментов (`FileTools.Definitions` строятся
и кэшируются на сеттинг, вне фэнтези прогоняются через `Genre.Localize`), результаты инструментов и сводка `BuildStateNote`
(тоже `Genre.Localize`), каталоги (`ItemCatalog.All`, `PortraitCatalog.All`, `SkillIcons`, `HeroAvatars`),
торговцы и категории (`ItemEconomy`), добыча (`LootTables`), архетипы классов (`Progression.Archetypes`),
навыки спутников, колёса дороги и слухов, шаблоны файлов кампании, окно создания героя и подписи интерфейса.

- Кампания запоминает сеттинг при создании (`RpgState.GenreId`, пусто = фэнтези). Кампания чужого сеттинга
  не открывается: `Chat.razor` показывает «Кампания из другого мира» с кнопкой смены темы, книга героя скрыта.
- Смена темы перезагружает страницу целиком (`forceLoad`), чтобы каталоги и панели перечитались.
- Глобальный `Genre.Current` — осознанное упрощение: одно приложение на одного игрока.
- Добавляя механику с текстом для модели, проверьте, что она звучит верно во всех сеттингах: короткие подписи —
  `Genre.Pick(фэнтези, киберпанк, современность)` (двухаргументного варианта нет нарочно — компилятор не даст
  забыть сеттинг), термины — `Genre.Money/MoneyGen/Coin/Mana`, длинные фэнтезийные фразы — словари в `Genre.Localize`.
  Развилки вида `Genre.IsCyber ? … : …` компилятор не ловит — при добавлении сеттинга ищите их поиском.
- Правки механики в промпте вносите во все три промпта (`GmPrompt.Default`, `CyberDefault`, `ModernDefault`).
  У новых промптов нет списка прошлых хэшей: нетронутый текст опознаётся флагами `SystemPrompt*IsDefault`.
- Вещи киберпанка и современности несут механику в самом каталоге (`cyber-items.json`, `modern-items.json`: урон,
  броня, цена, категория торговли, стрелковое/фехтовальное, вес доспеха) — `ItemStats.Register` и `ItemEconomy`
  берут её оттуда. Типы противников современности: humanoid, beast, vehicle (машины, вертолёт), drone.
- Статические таблицы инициализируются в порядке объявления: общий список (`AllCategoryKeys`) объявляйте раньше
  таблиц, которые его используют, иначе в них окажется `null`.

## Локализация (Русский / English)

- Текущий язык хранится в `HarnessSettings.Language` и выставляется глобально через `Lang.Current`; пустое значение
  означает, что игрок ещё не прошёл окно выбора языка при первом запуске. Русский — исходный и резервный язык.
- Короткий текст пишите парой `Lang.T("по-русски", "in English")`. Если текст одновременно зависит от сеттинга
  и языка, используйте `Genre.PickT(фэнтезиRu, киберпанкRu, современностьRu, fantasyEn, cyberpunkEn, modernEn)`.
  Не делайте отдельные проверки `Lang.IsEn` и `Genre.IsCyber`, если ту же развилку выражает `PickT`.
- Названия и английские ключевые слова предметов и портретов лежат в `wwwroot/sprites/i18n/en.json` и читаются
  через `CatalogEn`. Стабильные `id` в основных каталогах не переводятся и не переименовываются; если добавлен новый
  предмет или портрет, рядом с русской записью добавьте английское имя и слова поиска в `en.json` с тем же `id`.
- У мастера шесть базовых промптов: русский и английский для каждого из трёх сеттингов (`GmPrompt.Default`,
  `CyberDefault`, `ModernDefault` и их варианты `DefaultEn`, `CyberDefaultEn`, `ModernDefaultEn`). Изменение правил
  в одном промпте переносите во все шесть. Перед правкой русского `GmPrompt.Default` по-прежнему сохраните его старый
  SHA-256 в `PreviousDefaults`; английские нетронутые промпты опознаются отдельными флагами настроек.
- Большие каталоги и таблицы держите синхронными по стабильному `id`: английский текст размещайте рядом с русским
  (в соседней таблице или partial-файле `.En.cs`), чтобы набор записей и порядок можно было механически сверить.
  Текст для UI, результата инструмента, сводки состояния, шаблона кампании и сообщения модели должен переключаться
  одним и тем же языком — не оставляйте русскую строку как скрытый fallback там, где её увидит английский мастер.

## Промпт мастера (`GmPrompt.Default`)

- Промпт хранится в настройках. Если он совпадает с базовым (`SystemPromptIsDefault`), при выходе новой версии
  он обновляется сам, правки игрока не трогаются.
- **Перед любой правкой `GmPrompt.Default`** посчитайте SHA-256 текущего текста (нормализация: без `\r`, `Trim()`,
  UTF-8, hex в нижнем регистре) и добавьте его в `PreviousDefaults` с комментарием. Иначе у тех, у кого файл
  настроек старого формата, старый промпт «залипнет».
- Динамика (числа, списки, этап) — не в промпте, а в `BuildStateNote` и описаниях инструментов.
- Правила боя в промпте, `docs/CombatSystem.md` и шаблоне `Rules.md` должны совпадать — меняйте их вместе.

## Игровые системы

**Бой.** Правила — `docs/CombatSystem.md` (§12a — что считает код). Противники — `Adversary` (ХП, щит, КБ, атака, урон, DC,
стойкость, легендарные действия, эффекты, тип существа, мораль). Бой: `plan_encounter` → `initiative roll_all=true` →
действия `resolve_attack` (бросок, КБ, урон, крит, щит, сопротивления, «слом», мораль — всё кодом) → `combat_turn advance`
(тик длительностей в конце хода, DOT/регенерация и пропуск хода под контролем в начале). События `resolve_attack`/`combat_turn`
идут в журнал через `CombatEvents` (кладёт `FileTools`, забирает `BattleLogFeed.Feed` сразу после вызова). Ручной путь
(`roll_dice` с `attacker/target/check/dc/bonus` + `hp_delta` с `source`) остался для нестандартного.
«В бою» — это `Adversary.InFight` / `RpgState.InCombat()` (жив и не бежал/не сдался), а не `HpCurrent > 0`: проверяйте бой только ими.
Эффекты — строки «Название (N р.)»; добавляйте и снимайте их через `CombatEffects.AddOrRefresh/Remove`, а не `List.Add`.

**Прогрессия и баланс** (`docs/Progression.md`). Стандартный герой уровня L и рядовой враг того же уровня
откалиброваны так, что бой «на равных» длится 3–4 раунда и снимает ~22–41% ХП группы на любом уровне 1–30.
Сложность `plan_encounter` не берётся из таблицы, а измеряется Монте-Карло против реальной группы.
Ключевые понятия: архетипы классов (`Progression.Archetypes`), кость мощи К (урон оружия и навыков растёт с
уровнем), роли врагов minion…arc_boss, 600 опыта на уровень, `level_up` вместо ручного повышения.
Опыт `award_xp encounter=true` дают только за выбывших (повержен, бежал, сдался); `roll_loot` — с поверженных и сдавшихся.
**После любой правки формул прогоните калибровку** (см. «Проверка») — таблица должна остаться ровной по уровням.

**Предметы.** `GridItem` в сумке 11×5 (тетрис), `EquippedItem` в слотах (`EquipSlot`). Редкость
common → legendary; бюджет бонусов по редкости растёт на 10% за уровень предмета (`ItemStats.Budget`), атака и
КБ вещи ≤ +3; лишнее харнес урезает (`ItemStats.Balance`) и сообщает модели. Легендарное — только при
«разрешении» (`RpgState.LegendaryTokens`: колесо дороги, финал арки), иначе понижается до эпического.
**Золото никогда не предмет** — только счётчик `gold`. Добыча — `roll_loot` (`LootTables`): магические вещи идут через
копилку (~3,6 на уровень), остальное — мелочь и трофеи на продажу; после правок прогоните калибровку из `docs/Progression.md` §6.

**Спутники.** До трёх (`PartyMember`, у них есть `Role` и `Equipment`). Новый — только через
`ask_companion_role` (игрок выбирает абстрактную роль) → `recruit_companion` (харнес собирает лист на уровне
героя); `update_party_member` нового спутника не создаёт и отвечает ошибкой с подсказкой по воронке. Вещи спутника меняются только с его согласия (`transfer_party_item`, `consume_item` с `consent`).
Спутники действуют в бою сами; не обгоняют героя по уровню.

**Торговля.** `set_merchant` генерирует ассортимент по типу торговца и размеру поселения (`ItemEconomy`),
`open_trade` открывает окно, итог сделки приходит в чат сообщением «🛒 …». Именные артефакты (`Art` в каталоге)
в обычных лавках не продаются.

**Мир.** Города (`update_city`, крупные — с гильдией), гильдия приключенцев с рангами F…S, задания, сюжетные
арки (одна активная), NPC трёх категорий (important / nearby / notable), колесо дороги (`travel`, бросок d100
делает код), колесо слухов (`buy_rumors` / `recall_rumor`), события мира.

**Время, отдых, часы, фракции.** `RpgState.Day`/`DayPart` двигают `travel` (дни пути), `rest long` (утро следующего дня)
и `set_world_state` (`day_part`, `days_passed`); от дней сами тикают часы с `per_days` (`StoryClock`), заполнение
сообщается мастеру в результате инструмента. ХП и ману восстанавливает только `rest` (short ≤2 между long; ночная
тревога в диких местах, паёк из сумки вне поселения; прерванный отдых продолжается `resume=true` по `PendingRest`).
Тайные часы не показываются игроку (панель «Мир», `Worldstate.md`, подпись вызова в чате). `FactionStanding`: −100…100 и
метка (враги … союзники). Проверки героя — `skill_check` со степенями успеха (блестящий / успех / ценой / провал).

## Графика

Подробно — `docs/ArtPipeline.md`.

- Портреты — `wwwroot/sprites/portraits.json` (собирает `tools/sprites/build_portraits.py`) + `PortraitCatalog`.
  Модель выбирает смысловой id; если облик не похож на имя существа, харнес подбирает по имени. Старые адреса
  `classic:N`/`humanoid:N`/`monster:N` поддерживаются.
- Цветовые вариации врагов — `tools/sprites/build_variants.py` (маскированный сдвиг оттенка исходных клеток).
- Иконки предметов — тайлы DCSS (CC0), атлас `rpg-items.png` + `items.json` + `css/pixel-items.css`
  (собирает `tools/sprites/build_items.py`, тайлы кэшируются в `tools/sprites/.cache`).
- Иконки навыков — `SkillIcons` (лист `combat-icons-loot.png`, 8×8).
- **Современность нарисована кодом** (`build_modern_*.py`, переиспользуют кисти киберпанка в приземлённой палитре):
  предметы `modern-items.png/json` + `css/pixel-modern.css` (id `md_`), портреты `modern-enemies-street/threats.png`,
  `modern-persons.png`, `modern-hero-avatars.png`, навыки `modern-skill-icons.png`, меню `modern-book-menu.png`.
- **Киберпанк нарисован кодом** (`tools/sprites/pixelkit.py` и `build_cyber_*.py`): предметы `cyber-items.png/json` +
  `css/pixel-cyber.css` (id с префиксом `cy_`), портреты `cyber-enemies-street/machines.png`, `cyber-persons.png`,
  `cyber-hero-avatars.png` (регистрируются в `build_portraits.py` с `genre`), иконки навыков `cyber-skill-icons.png`
  (тот же порядок 64 клеток) и меню досье `cyber-book-menu.png`. Пиксель-арт 32/64 px, увеличенный без сглаживания.
- **id портретов и предметов и порядок записей — только дописывать.** Они сохранены в кампаниях; позиция в
  атласе предметов = порядок в `CATALOG`, клетка портрета = порядок в `VARIANTS`.
- Новых «живописных» картинок на этой машине не сгенерировать (у LLM-сервера нет модели изображений) — только
  внешний генератор по промптам из `docs/ArtPipeline.md`, перекраска, DCSS или процедурный пиксель-арт кодом.
  Живописный лист киберпанка можно положить поверх кодового с тем же именем файла и порядком клеток.
- Новые файлы в `wwwroot` попадают в манифест статических файлов только после `dotnet build`.

## Подводные камни

- Файлы — UTF-8 без BOM, переводы строк LF. Python в Windows по умолчанию пишет CRLF: открывайте с `newline="\n"`.
- `Bash`-heredoc с многострочным Python и кавычками в этом окружении ломается — пишите скрипты правок в файл.
- `JsonNode.ToJsonString()` экранирует кириллицу `\uXXXX` (×6 символов). Для оценки размера используйте
  `FileTools.DefinitionsChars` / `UnsafeRelaxedJsonEscaping`. Контекст оценивается как «символы / 4».
- Числа во inline-стилях — только через `CultureInfo.InvariantCulture` (`Css.cs`), иначе русская запятая ломает CSS.
- Scoped CSS компонентов собирается в `obj` и копируется в `wwwroot/RPG_Harness.styles.css` после сборки — правьте
  `*.razor.css`, не бандл.
- Цвета оформления — только токены. Полупрозрачный акцент пишется `rgba(var(--rh-accent-rgb), .5)` (три числа
  объявлены рядом с `--rh-accent`), а не вписанной латунью `rgba(201,165,92,…)`: жёсткое значение тема не
  перекрасит. Новая тема — блок в `css/themes.css` плюс строка в `UiThemes.All`; `--rh-accent-rgb` обязателен.
  Правила формы темы пишутся с префиксом `html[data-theme="…"]` — иначе scoped-CSS компонентов (подключён позже)
  перебьёт их. `::deep` в глобальном CSS недопустим: браузер отбросит всё правило вместе со списком селекторов.
  Тема применяется атрибутом `data-theme` на `<html>` (`App.razor`) и мгновенным `window.harness.setTheme`
  со страницы настроек; выбор темы сохраняется сразу, отдельно от кнопки «Сохранить».
- `PortraitCatalog` — статический, грузится в `Program.cs`; в тестах вызывайте `PortraitCatalog.Load(<wwwroot>)`.
- В тестах через CDP `innerText` учитывает `text-transform`: в киберпанке кнопки пишутся капителью — ищите по `textContent`.
- Сохранения старых версий должны открываться: новые поля — со значениями по умолчанию, пустые поля трактуются
  «по-старому» (например, пустой `Role` → архетип угадывается по классу, `Level` предмета 0 → 1).

## Стиль кода

- Комментарии и `/// <summary>` на русском, объясняют «зачем», а не пересказывают код.
- В Razor-компонентах местами очень плотный однострочный код (`BattleWindow`, `RpgPanel`) — при правках держитесь
  стиля окружения, не переформатируйте чужие блоки.
- Результаты инструментов — законченные фразы по-русски, с итоговыми числами; не заставляйте модель считать самой.

## Проверка

- `dotnet build` — без ошибок и предупреждений.
- **Логика без LLM.** Отдельный консольный проект вне репозитория (`Sdk.Web`, `EnableDefaultCompileItems=false`,
  `<Compile Include="…\Services\*.cs" />`, пакет Markdig) и заглушка `IWebHostEnvironment` с `WebRootPath` на
  `wwwroot`. Так можно вызывать `FileTools.Execute` на состоянии в памяти (рабочая директория в настройках пуста)
  и гонять калибровку `Progression.Simulate` / `Progression.Monster`.
- **Интерфейс без настоящего LLM.** Запустите собранную DLL с временной конфигурацией:
  `dotnet bin/Debug/net10.0/RPG_Harness.dll --contentRoot <tmp> --webroot <repo>/wwwroot --urls http://127.0.0.1:5310`,
  где в `<tmp>/.harness/settings.json` адрес API указывает на фейковый OpenAI-совместимый сервер, отвечающий
  `{"choices":[{"message":{"content":…,"tool_calls":[…]}}]}`, а `workDirectory` — на временную папку.
  Так не трогаются настоящие настройки, кампании игрока и его LLM-сервер.
- Скриншоты и проверки страницы без браузера пользователя — `node tools/cdp.js --url … --js … --shot …`.
